## 2. Detailed Technical Debt Registry

### TD-01: GUI Architecture (`egui` vs `nih-plug` VIZIA)
- **Context:** [D11](DECISIONS.md) envisioned unified VST3/CLAP DAW plugin export alongside standalone via `nih-plug`. `crates/nord-gui` was developed with `eframe` and `egui` to deliver rapid cross-platform GUI interaction, crisp OLED graphics, and responsive control surface widgets.
- **Debt:** Currently, the standalone runner is decoupled from DAW plugin host automation interfaces.
- **Remediation Plan:** When implementing `crates/nord-plugin`, either wrap the `egui` canvas using `nih_plug_egui` (unifying standalone and VST3/CLAP UI) or provide standard parameter automation bridges between `nih-plug` parameters and `Stage4PanelState`.

### TD-02: MIDI & Audio Device Selection
- **Context:** `audio.rs` auto-selects the system default CPAL output device and the first available MIDIR input port.
- **Debt:** Users with multiple MIDI controllers (e.g. secondary keyboard or pedalboard) or dedicated ASIO/CoreAudio interfaces cannot switch devices from a GUI settings menu.
- **Remediation Plan:** Introduce a modal settings dialogue or menu bar to list available CPAL audio devices, buffer sizes, and MIDIR input ports.

### TD-03: Piano Engine SFZ Multi-Sample Loader
- **Context:** The Piano engine (`crates/nord-core/src/piano.rs`) provides 120-voice polyphonic velocity tracking, touch curves, and undamped sympathetic resonance, but uses deterministic in-memory wavetable synthesis.
- **Debt:** Clavia's proprietary `.npno` / `CNSP` sample binaries are opaque and compressed without public decoders. Full acoustic realism requires real multi-velocity samples.
- **Remediation Plan:** Implement an open SFZ multi-sample parser and streaming voice reader (e.g. using Salamander Grand or VSCO-2 CE Upright).

### TD-04: Organ Tone Sources, Weights and Contact Bounce
- **Context:** Model to DSP path map: [D21](DECISIONS.md#d21-organ-model-to-dsp-path-map). Pipe1 / Pipe2 = bank `0x122620` + mix stage `0x12268F`, default `ToneWheelSource::ModelDefault` resolves to the firmware bank (`organ/firmware_bank.rs`; `u32` phase, `>> 20`, 4096-point x table, exact 12-TET ladder, vibrato detune table; VERIFIED against the oracle, [organ-tonewheel-bank](research/organ-tonewheel-bank.md), [organ-oracle-audio](research/organ-oracle-audio.md)), with the firmware vibrato detune table and lane matrix when vibrato is on (the old `COPY_SPREAD_CENTS` pair is removed). B3 = generator `0x121BBE` + processor `0x121E2B`; its octave-locked pitch ladder (bit exact) and wheel tables are the opt-in `ToneWheelSource::B3Wheels` ([organ-engine](specs/organ-engine.md) 3.1.6, [b3-generator](research/b3-generator.md)). Gains, level, the two stereo lanes and the per-wheel ARM weights with smoothing (`WeightMode::Firmware`, VERIFIED: level 1.0000x, attack and release within 0.1 %) are ported (3.1.4, 3.1.5).
- **Debt:** (a) B3 `Legacy` stays the default: the per-wheel amplitude `A` and per-key footage weights `W` are applied by `B3Wheels` (captured, 24 keys), the tail's phase, the dry gain writer and the multi-write `A` words are open (OQ16, [organ-keydown-weights](research/organ-keydown-weights.md)); the DSP frame rate is settled at 43,402.34 Hz ([dsp-frame-rate](research/dsp-frame-rate.md)). (b) Vox (`0x12272D`, `0x1229B3`) is ported as opt-in `ToneWheelSource::Vox` (84 oscillators, three output sections; 36-sine bank unported, 21-entry note one-pole ratio list EMPIRICAL, key map VERIFIED from the key-down capture, oscillator start phases ASSUMED); the writer of its key flags and the footage-edit to level-slot map are unknown (OQ17). (c) Farfisa: the generator `0x122A71` is bit-exact and ported as opt-in `FarfisaWheels`; the processor `0x122B85` (ARM weights and filter tables never captured) and the B3 Bass processor `0x122296` (scanner, 8' / 16' windows; replayed, chord verified) are not ported (OQ18, OQ19). (d) The level `L`, the velocity source, the key-up `a` and the percussion path (second engine family) are open (OQ19), so `WeightMode::Legacy` stays the default. (e) Contact bounce is still the simple bandpass noise burst.
- **Remediation Plan:** The key-down capture is done (B3 `A` / `W` tables, Vox key map). Next: the B3 tail's phase and per-key `A` (OQ16, [organ-b3-tail](research/organ-b3-tail.md)), the Vox oscillator start phases and sine bank (OQ17); flip a default only under [D22](DECISIONS.md#d22-opt-in-firmware-paths-in-nord-core-defaults-change-only-when-verified-end-to-end). Replace the key-click model with a contact-bounce network last.
- **Update (Pipe video gap):** [pipe-video-gap](research/pipe-video-gap.md): the Pipe2 clip of the Part A video (Space Drama II) also has two synth layers on and is synth-dominated (synth section alone scores 2.45, organ alone 6.4 to 6.5, mix 4.95). The product Pipe2 layer matches the oracle to 0.00 dB per line on three chords in both weight modes (`organ/pipe_lines.rs`, VERIFIED), so the bank, mix stage, ladder and foldback are not the cause of the -11 dB brilliance; the `Legacy` Pipe waveform scores better only because its -7.4 dB second harmonic (firmware: -19 dB) fills the synth's treble deficit. Default unchanged, `render_hash` unchanged. Open: a Pipe-only hardware clip, the organ level `L` (Legacy bus is +14.4 dB over the ARM weight unit), wheel steps from the ARM words (0.35 cent anchor, 0.055 cent table).

### TD-05: Pre-Allocated Boxed Buffers in `Stage4Engine`
- **Context:** Windows thread stacks are limited to 1 MB by default. Initializing 7 layer delay lines, FDN reverb matrices, and scanner buffers on the stack caused stack overflow (`0xc00000fd`).
- **Debt / Trade-off:** Buffer memory is allocated on the heap inside `Box::new()` during initialization (`Stage4Engine::new()`).
- **Status:** **Accepted Architecture Invariant**. Real-time DSP rendering (`render_frame` / `process_block`) remains strictly zero-allocation and lock-free.

### TD-06: Firmware Internal SHARC / ARM0 Symbol & Lookup Table Mapping
- **Context:** `CNSP` decompression, full-stream Clavia LZO1X firmware decompression (`Image 1` `798,912 B`, `Image 0` `5,499,504 B`), `ARM0` MurmurHash2 resolver (`0x0a5a44`) and the 5x128 DSP parameter tables are mapped and wired into `nord-core` and `nord-gui` ([sharc-dsp-and-preset-hash-teardown](research/sharc-dsp-and-preset-hash-teardown.md)). The five DSP images (FX, PNO, ORG, SY1SY2, SMP; 916,780 bytes, `0x44667C..0x5263A8`) are cut and loaded ([dsp-image-hunt](research/dsp-image-hunt.md)); `crates/nord-sharc` decodes and runs them ([sharc-core](specs/sharc-core.md)); the ARM download call (`0xC0241C58`) and the message format are decoded ([arm-dsp-protocol](research/arm-dsp-protocol.md)); the host firmware boots to its main loop under `unicorn` ([arm-fw-emulation](research/arm-fw-emulation.md)).
- **Remaining Debt:** Key-down and keybed link are not emulated; SPI/flash downloads (sample maps, stroke tables) are stubs; SPI0 vs SPI1 and the 2157x peripheral probes P1..P8 are open (OQ15); many routines still lack an ARM-side writer (OQ16..OQ22). Oracle runs of long passes are slow (ROADMAP 7b.1).
- **Remediation Plan (Track B, [D12](DECISIONS.md)):** Phase 7b in [ROADMAP](ROADMAP.md). `bank1_CODE.bin@0x08cb7c..0x09fe8` is a region/test table, not a loader table.

### TD-08: Sample Interpolation Kernel
- **Context:** The firmware's synth DSP image holds six 12-tap x 256-phase Kaiser-windowed sinc kernels (`docs/research/sy-dsp-map.md` section 2; `beta = 8.5`, half width 6, cutoffs 1.10, 1.05, 1.00, 0.96, 0.925, 0.895; max error 5.9e-8 = one float32 ulp, VERIFIED by `tools/ns4_sinc_check.py`). `crates/nord-core/src/sinc.rs` now implements this exact closed form (resolved: the earlier 3-term cosine window was a fit with rms 3.6e-5) and measures at least 5x lower error than the current 4-point Catmull-Rom on a 0.3 fs sine. The only DSP reader is the SY1SY2 resampler at `0x1C10EE`; no DSP instruction writes the voice's kernel pointer, so kernel selection is ARM-side.
- **Debt:** the synth sampler is wired (`SAMPLE_INTERPOLATION = Sinc` in `synth/sample_osc.rs`; `cubic_pcm` stays as the switchable legacy path; cost: interpolator 5.3 -> 14.0 ns per sample, whole layer unchanged within noise, see `docs/specs/synth-engine.md` section 7). **Piano part resolved:** the piano sample path uses the exact SMP 6-tap x 256-phase Q31 kernel (`crates/nord-core/src/piano/q31_kernel.rs`, `SampleInterp::SmpQ31` default, `Cubic` kept as a switch): Hamming-windowed sinc with additive DC normalisation, bit-exact (VERIFIED, [smp-kernel-fit.md](research/smp-kernel-fit.md)). Open for the piano part: edge handling at stream start and end (the Rust path repeats edge samples, ASSUMED) and the ARM-side voice record (width, scale). The rule that picks a synth kernel from the playback ratio is not decoded: `SincKernelSet::select` is ASSUMED (nearest `fc` to `min(1, 1 / ratio)`); confirm by tracing the ARM literal `bank0_CODE@0xC0001BAC`. The 12-tap float sinc is the synth path only.
- **Oracle comparison ([oracle-vs-engine.md](research/oracle-vs-engine.md)):** against the Stage B routine run on the SHARC oracle, `SincKernelSet` is within 1 ulp (5.96e-8 abs) per output frame. Both differences found are fixed in `sinc.rs`: `interpolate` floors the 8-bit phase like the hardware (was nearest, 3.4e-3 error on a 0.3-sample start) and the cutoffs are f64 decimals (table max error 1.19e-7 -> 5.96e-8, bit-identical values 4,153 -> 9,355 of 18,432). `SincKernel::interpolate_ext40` (`sinc/ext40.rs`) reproduces the DSP's 40-bit accumulation for tests only. Open: edge handling (the engine repeats edge samples, the hardware ring is circular) and unity gain (engine multiplies by `fc`, firmware applies the voice gain).
- **Remediation Plan:** Done for the synth and piano paths (sample-mode tests re-run, golden diff limited to `SAMPLES`). Remaining: confirm the kernel-per-ratio rule (ARM trace).

### TD-11: Firmware Synth Saw and Gain De-zipper Not Default
- **Context:** [synth-voice-control](research/synth-voice-control.md) sections 4 and 5 verify, in the SHARC oracle, the falling two-increment PolyBLEP saw with high-pitch fade (helper `0x12501F`) and the 0.979-per-frame voice gain smoother. - **Debt:** The defaults stay `Classic` / `Zdf` / `Legacy` and off. The pieces are wired as one opt-in chain, `SynthChain::FirmwareStrip` (`synth/strip_path.rs`, `strip_map.rs`, `render-patch --synth-chain strip`, [synth-strip-path](research/synth-strip-path.md)), and its stage words match the oracle (envelope records 2 x 15 passes bit exact, cutoff `R` 3.5e-6, filter 7.5e-7), but these stay ASSUMED: the panel value to strip word / rate index maps (cutoff Hz, attack and decay times, tau = 0.18 x displayed time, 2 frames per pass, resonance), which strip stage the Wave selects (the decoder's SHAPE `Triangle` is a placeholder that plays as a saw in the strip chain), the output sign, the 1 kHz ARM tick, the start state of a voice's gain, the key-down gain series and the controller modulation of the rate index. The SY frame rate is VERIFIED at 43,402.34 Hz ([dsp-frame-rate](research/dsp-frame-rate.md)); `SawModel::FirmwareSy` applies the fade knee at that rate (the strip chain uses it; `Firmware` still uses the engine rate). Pulse and triangle keep the textbook shapes; the classic amp envelope is not smoothed. For the filter: `kFltType` to stage map and the `0x1257B2` ladder-like stage (order-4 real-pole system, poles measured, laws open) are not ported.

### TD-12: Standalone Program Edits Allocate on the Audio Thread (Resolved)
- **Context:** The standalone engine is owned by the audio callback, so `AudioCommand::Program(ProgramEdit)` used to run the allocating `nord_core::engine` operations (layer init, copy / paste / swap, undo snapshots, `capture_state`, `apply_state`) inside the callback, and stored programs travelled back as `Box<ProgramState>` over an unbounded channel.
- **Resolution:** `crates/nord-gui/src/audio/control/` runs those edits on the control thread against a shadow engine and sends the audio thread one allocation-free `SwapState` (`Stage4Engine::swap_state`, moves only); the old state returns through a bounded channel and becomes the Undo / Redo snapshot there. Snapshots (STORE) are answered by the control thread directly. Spec: [program-handoff](specs/program-handoff.md).
- **Evidence:** `crates/nord-gui/tests/no_alloc_program_ops.rs` (counting global allocator): the legacy `LayerInit(All)` applied on the audio thread made 79 allocator calls (`the_old_path_allocated_on_the_audio_thread`); with the fix every control op (layer init all / organ / synth, undo, redo, copy, paste layer / fx / morph / program, swap, clear morph, recall) makes 0 allocator calls in the callback loop (`every_control_op_is_allocation_free_on_the_audio_thread`, `recall_and_snapshot_are_allocation_free_on_the_audio_thread`). Unit tests: `engine::handoff::tests`, `audio::control::tests`.
- **Remaining (not part of TD-12):** `LoadProgram`, `LoadPianoSound` / `LoadSynthSample` (dropping the last `Arc` of a sound) and `AudioHandle::send_midi`'s timed retry for critical events still run or block outside the strict no-lock / no-free rule; the shadow engine is a replay of commands, so a state change that only the audio thread makes (not via a command or non-note MIDI) is invisible to STORE until it is replayed.

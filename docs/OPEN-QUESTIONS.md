- **FX biquad table layout (`0x2f730c`, 18x128 `f32`):** rows come in 3 groups of 6 (`A, B, A', B', C, C'`; group 0 idx0 = `1.9496, 0.3493, 1.9440, 0.3436, 0.0093, 0.0094`; group 1 `A` reaches `3.76`, so rows are not plain `a1/a2`). Cascade form, per-group purpose, and idx-to-Hz map are unknown without disassembling the consumer near `0x1bf094`. `fx.rs` uses RBJ designs, not these rows.
- **Stage gain table (`0x2ae5b4`):** 19 entries equal `10^((i-12)/20)` (`-12..+6 dB`, 1 dB steps, exact to 1e-6) plus a `0.0` terminator. Consumer unknown; EQ is `+-15 dB` in 0.25 dB steps, so this is not the EQ gain.

- **Biquad table consumer (disassembly, OS v1.66 `bank0_CODE.bin`, ARM mode):** literal pool `0x1bf094 = 0xc02f730c` (table base). The sender function starting `0x1be108` (pool `0xc02f8b10` = group 1 row 6 + 4, row pointers `+0x1fc`/`+0x3fc` apart) does **not** compute filters: it derives an index with soft-float `double` math (`0x25d2a4`, `0x270a38`, `0x270e18`, ...), then copies table words to the SHARC through the DSP-comm call `0x6ca48` in a loop with stride `0x10`. Coefficients are consumed by SHARC code; a structural scan of the decompressed segments found no DSP image in them (`bank0_CODE`: ARM code `0x0..0x278000` (>0.9 of words with condition `0xE`), then data: float tables, 16-bit PCM-like data at `0x300000..0x438000` (entropy 7.4, first bytes `cc fa 41 fa 41 fa 99 fe`), no 6-byte SHARC word periodicity; `bank1_CODE`: ARM code to `0x8c000`, then pointer tables / low-entropy data). VERIFIED by scan only for those two segments (script in session, heuristic: ARM-condition fraction + byte entropy); not proof that no DSP image exists elsewhere, e.g. compressed or in SPI flash. The exact filter form is still unknown. `ASSUMED` hypothesis: per group, rows `A,B,A',B'` are two cascaded sections' feedback terms and `C,C'` feedforward terms; no fit to `a1/a2`, `1-a+b` or DC-gain relations was found. Next: decode the double-math index mapping (idx to Hz/Q) and obtain the SHARC `.ldr` from mainboard SPI flash.

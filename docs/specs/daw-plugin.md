# DAW Plugin

## Scope

`nord-plugin` exports CLAP and VST3 wrappers around `Stage4Engine`. Hosts own and restore the NIH-plug parameter state. The plugin synchronizes those values into the engine before processing each audio block.

## Host parameters

- Global controls include master level, BPM, compressor amount, scene selection, split enable, three split notes, and three split crossfade widths.
- Organ A and B each expose nine drawbars. Shared organ, piano, and synth controls map into their respective engine layers.
- Morph assignment: `morph_assign` (module `morph_assign.rs`) exposes signed Wheel / Pedal / Aftertouch depths (`-1.0..=1.0`, default `0.0`) for the 7 layer levels (`morph_level_{wheel,pedal,at}_1..7`, order Organ A/B, Piano A/B, Synth A/B/C) and the 3 synth cutoff slots (`morph_cutoff_{wheel,pedal,at}_1..3`). `sync_to_engine()` writes only the deltas; the base values stay owned by the level / cutoff parameters. Depth range and default are `ASSUMED` (engine delta domain); hardware depth scaling is unverified.
- Per-layer FX: `layer_fx` (module `fx_params.rs`) exposes 11 controls for each of the 7 layers (`fx_{drive,eq_bass,eq_mid,eq_treble,comp_on,comp_amt,delay_on,delay_ms,delay_fb,delay_mix,rev_mix}_1..7`) mapped onto `Stage4Engine::fx_chains[i]`. EQ range +-16 dB is `VERIFIED` against the 7-bit x 0.25 dB preset field; delay 20-1500 ms follows the hardware table; defaults equal `LayerFxChain::new`. Because `sync_to_engine()` runs every block, host values override FX loaded from `.ns4p`.
- Per-layer Organ live (A/B = `_1`/`_2`): `organ_live` (module `organ_live_params.rs`, prefix `organz`) exposes `organz_{poly_perc,drawbar_live,sync,live1..live9}_{1,2}` and the shared `organz_shared_vibrato`. Poly percussion, Drawbar Live (`live1..9` are the physical bars used while `drawbar_live` is on), SYNC (while on, the physical bars are copied into the stored preset) and Vox/Farf vibrato sharing map to the engine fields in `docs/specs/organ-engine.md` s3.3.1. Defaults equal the engine defaults; test `poly_percussion_changes_rendered_audio_and_stays_finite` proves poly mode changes the audio.
- Per-layer Piano extras: `piano_layers` (module `piano_params.rs`) exposes `pianox_{soft_release,unison,dyn_comp,octave}_{1,2}` (Soft Release on/off, Unison 0-3, Dyn Comp 0-3, Octave Shift -2..2) and copies them to `engine.piano_a/b` in `sync_to_engine`. Ranges follow the engine fields; the manual (p.23-26) gives Unison 1-3 and Dyn Comp 1-3 plus Off. Ids are snapshotted in `param-ids.snapshot`.
- Synth pattern edit (module `synth_pattern_params.rs`, prefix `synthp`): `synthp_{zigzag,range_frac,pat_custom,pat_len}_{1,2,3}` and `synthp_step_{gate,accent,pan}_{step 1..16}_{layer 1..3}` (144 step ids), additive, defaults equal `SynthLayer::new`; synced after `synthg`.
- Per-layer Synth extras: `synth_layers` (module `synth_params.rs`) exposes `synthx_{unison,voice,priority,glide,kb_track,filter_env,osc_env,osc_env_pitch}_{1,2,3}`: Unison 0-3, Voice Poly/Mono/Legato, Note Priority Last/Lo/Hi, Glide 0-4 s/oct (scale `ASSUMED`, see `SynthLayer::glide_sec`), KB Track Off/1/3/2/3/1, bipolar Filter and Osc Env amounts, Env To Pitch. Defaults equal the engine defaults, so an untouched host leaves sounds unchanged. Test `unison_param_changes_the_rendered_signal` renders Synth A with unison 0 vs 3 and checks the output differs. The shared `synth_*` ids still drive all three layers (D16). LFO, Arp and Vibrato are in `synth_mod_params.rs` as `synthm_{lfo_shape,lfo_dest,lfo_rate,lfo_amount,arp_mode,arp_range,arp_rate,vib_mode,vib_rate,vib_depth,vib_delay}_1..3` (defaults equal `SynthLayer::new`; vibrato depth cents scale `ASSUMED`; tests render LFO-to-pitch and vibrato against Off). Gate, Pattern presets, KB Hold, KB Sync and Master Clock sync are in `synth_gate_params.rs` as `synthg_{gate_mode,gate_env,pat_on,pat_preset,hold_excl,kb_sync,arp_sync,arp_div,lfo_sync,lfo_div}_1..3` plus global `synthg_kb_hold` (synced after `synthm`; Gate needs the arp run switch on; defaults equal `SynthLayer::new`; tests: defaults, per-layer routing, Gate vs arp render). Not yet exposed: Pattern edit/accent/pan, Unison for samples. Pedals and Aux KB are in `aux_pedal_params.rs`: `ped_{swell_func,swell_gain,swell,ctrl_func,ctrl_gain,right,rotor_func,rotor,foot_func,foot}` and per layer `ped_{sustped,pstick,range}_1..7`, plus `auxkb_{enable,channel,curve,organ,piano,synth}` (synced after `synthm`; defaults equal the engine, tests: defaults, bit-identical default render, per-layer routing, CC4 not clobbered by an unchanged `ped_swell`, Aux layer routing). Extern layers have an engine API only; no host parameters. Triple Pedal assignments and Sustain Pedal Type are in `pedal_assign_params.rs` as `pedx_{sustain_type,tp2,panel,tp1_left,tp1_mid,tp2_left,tp2_mid}` plus momentary positions `pedx_{tp1_left_pos,tp1_mid_pos,tp2_left_pos,tp2_mid_pos}` (synced after `ped`; positions are pushed only when they move so MIDI `CC66` / `CC67` are not clobbered; defaults equal the engine; tests: defaults, bit-identical default render, selector and position routing, unique ids). Program Up/Down is not applied by the plugin (no host-side program list): `PedalState::take_program_step()` is the hook.
- Program area: `program_params.rs` exposes `prog_transpose` (IntParam -6..6) and `prog_level_db` (-12..12 dB, range `ASSUMED`), see `docs/specs/morph-and-zones.md` section 5 for the engine functions (Panic, Layer Init, Section Edit, Copy/Paste/Swap, Undo, Live slots). Defaults equal the engine; tests: defaults, values reach the engine and change the render.
- System / Sound / Output menu: `settings_params.rs` exposes `sys_{transpose,fine_tune,piano_noise_db,piano_res_db,tonewheel,click_high,rotary_balance,rotor_speed,rotor_acc,horn_speed,horn_acc,mono}` and calls `Stage4Engine::set_global_settings` (`engine/settings.rs`). Defaults equal `GlobalSettings::default()`; tests: defaults equal the engine, bit-identical default render, every value maps to its engine field, balance index covers 70/30..30/70, unique ids. The snapshot `param-ids.snapshot` gained these 12 ids only. The MIDI / Extern menus (`midi_menu_params.rs`, `midix_*`), the Output menu (`output_params.rs`, `outx_*`) and the Organ trigger point plus Foot Switch SW B (`menu_extra_params.rs`, `menx_*`) are additive host parameters whose defaults equal the engine (tests: defaults equal the engine, bit-identical default render, every value maps to its engine field, unique ids); the audio ports stay one stereo pair (outputs 1-2 of `OutputRouting`), Local Control is not a host parameter, and the on-screen keys follow Local Control through `handle_keyboard_midi`. See `docs/specs/midi-and-control.md` section 2b. The menu data model that names these ids lives in `nord-panel` (`menus/`), see `docs/specs/midi-and-control.md` section 5.
- Per-layer Organ extras: `organ_layers` (module `organ_params.rs`) exposes `organx_{b3_bass,octave,scanner}_{1,2}` plus `organx_close_mic` and `organx_stop_mode` (Rotary, copied to both organ layers). Defaults equal the engine defaults. Test `scanner_vibrato_changes_rendered_organ_audio` renders Organ A with scanner Off vs C3. Preset/Drawbar Live and Poly percussion are exposed by `organ_live` below.
- Per-layer Organ extras: `organ_extra` (module `organ_extra_params.rs`, prefix `organy`) exposes `organy_{model,key_click,rotary_on,mic_angle,fine_tune,crosstalk,detuned}_{1,2}`, applied after the global Organ block (`model` -1 follows `organ_model`). Defaults equal `OrganLayer::new`. Render tests cover each parameter (fine tune and detuned copies on Pipe1, the firmware bank). `mic_angle` range and `crosstalk` upper bound 2.0 are ASSUMED.
- Per-layer Piano extras: `piano_extra` (module `piano_extra_params.rs`, prefix `pianoy`) exposes `pianoy_{string_res,pedal_noise}_{1,2}`, ANDed with the global switches (the engine has booleans, no resonance amount). Render tests use a pedal-only and a held-note + pedal render.
- Per-layer Mod 1 clock division and Reverb VARIATION (module `fx_variation_params.rs`, prefix `fxz`): `fxz_{mod1_beats,rev_var}_{1..7}`. Defaults equal `LayerFxChain::new` (checked by `defaults_match_engine_defaults`); the ids are appended to `param-ids.snapshot`, none removed.
- Per-layer FX selectors: `layer_fx_selectors` (module `fx_selectors.rs`) exposes 13 controls per layer (`fxsel_{mod1_type,mod1_rate,mod2_type,mod2_rate,cabinet,comp_fast,delay_sync,delay_div,delay_pp,delay_flt,delay_fx,rev_model,rev_color}_1..7`) through host-side mirror enums of the `nord_core::fx` enums (variant order is the host index: append only). Mod rate ranges (0.1-20 Hz / 0.1-10 Hz) are `ASSUMED`; defaults equal `LayerFxChain::new`. Mod amounts, EQ mid frequency, filter resonance, amp/delay-effect variation flags and `delay_analog` are exposed by `fx_extra_params.rs` as `fxx_{mod1_amount,mod2_amount,eq_mid_freq,filter_res,amp_variation,delay_analog,delay_fx_variation}_1..7` (defaults equal `LayerFxChain::new`; mid freq 200 Hz-8 kHz per manual p.51; test `mod1_amount_changes_the_processed_signal` runs a tremolo through the chain at amount 0 vs 1). Mod 1 / Mod 2 VARIATION, Wah PED (`mod1_ped`, `mod1_ped_pos`), the Master Clock division (`delay_sync_beats`), GLOBAL mode (Delay, Compressor, Reverb) and GROUP mode (Piano, Synth) are exposed by `fx_sharing_params.rs` as `fxy_{mod1_var,mod2_var,mod1_ped,mod1_ped_pos,delay_beats,glob_delay,glob_comp,glob_rev,group}_1..7` (additive; defaults equal the engine, everything off). `delay_beats` index `n >= 1` is `DELAY_SYNC_BEATS[n-1]`, 0 keeps the plain division. Sharing flags name the focused source layer (lowest index wins); `sync_to_engine` writes `Stage4Engine::fx_sharing` and `process_block` applies the copies. `TO ROTARY` is the existing `fxsel_cabinet` value and is routed in the engine. Tests: `each_variation_and_division_param_changes_the_chain_output`, `to_rotary_and_global_reverb_change_the_rendered_engine_output`, `global_delay_and_synth_group_change_the_rendered_engine_output`.
- Parameter IDs are stable strings declared on `Stage4Params`; parameter ranges provide clamping in the host parameter system.
- `sync_to_engine()` maps split crossfade values 0, 1, and 2 to Off, Small, and Large. Split note values are MIDI notes 0–127.

## Appended FX enum variants and the param snapshot

`Mod1Sel` gained `Auto Wah` and `Pump`, `Mod2Sel` gained `Spin` and `Ensemble` (appended; `Mod1Type` / `Mod2Type` in `nord_core::fx` grew the same way). Growing an enum raises the `step_count` of `fxsel_mod1_type_1..7` and `fxsel_mod2_type_1..7` from 4 to 6 in `param-ids.snapshot` (regenerated with `UPDATE_PARAM_SNAPSHOT=1`). No id was removed or renamed and defaults stay at index 0 (Off); existing variants keep their index, only the normalized spacing of stored automation changes (hosts that store normalized values see Tremolo..Wah shift, unavoidable when appending to an `EnumParam`).

## Preset and state handling

- `PluginStateSnapshot` is a JSON serialization format. New fields use defaults so older version-1 snapshots remain readable.
- Snapshot JSON is not a mechanism for writing into NIH-plug parameters. Host parameter restoration must use NIH-plug's host/context state interface.
- `load_ns4p_into_engine()` parses a CBIN program and applies it to a caller-owned engine. Callers must invoke it before moving the engine into audio processing; it does not update host automation values.
- Raw memory writes into NIH-plug parameter structs are prohibited.

## MIDI and host verification

- OmniSplit routes supported MIDI events through the core split router. Multitimbral mode maps zero-based channels 0–6 to Organ A/B, Piano A/B, and Synth A/B/C; channels 7–15 fall back to OmniSplit.
- Pitch bend (`MidiPitchBend`) is decoded into `MidiEvent::PitchBend` and drives every layer with PSTICK on (range per layer, default 2 semitones; Synth, Organ and Piano) and Aux KB layers.
- Automated unit tests verify conversion, routing, parameter synchronization, state JSON compatibility, and program import. DAW host compatibility remains unverified until the plugin is loaded and exercised in each host.
- AUv2 is not exported or tested by this crate; external wrapper packaging is separate.

## Editor (Phase 6b B11, `ns4-hud1`)

`crates/nord-plugin/src/editor/` draws the same panel as the standalone app by calling `nord_gui::panel::render_stage4_panel` (`nord-gui` built with `default-features = false`, so no cpal, midir or eframe). `nih_plug_egui` and `nord-gui` both use egui 0.31.1, so the workspace has one egui.

| Aspect | Behaviour |
|---|---|
| Edit path | The panel sends `AudioCommand`s into a channel. Each frame the GUI thread drains it into a `ParamSink` (`PanelSink`): `begin_set_parameter`, `set_parameter_normalized`, `end_set_parameter` through the host `GuiContext`. The engine is never touched from the editor. |
| Read-back | Before each frame the panel state is refreshed from the parameter values (`readback.rs`: levels, layer enables, organ model/drawbars/percussion/rotary, piano selectors, global synth filter and envelope, mod wheel, FX knobs of the focused slot). Per-layer synth/organ detail kept in the panel's `ui_state` is not mirrored. |
| Keybed | Keybed MIDI goes through a bounded `crossbeam_channel` (256 events, array queue: no lock, no allocation) to `process()`, which drains it at the start of each block and routes notes like host MIDI (both routing modes). Mod wheel CC 1 is written to `mod_wheel` instead. |
| Size | Window size is persisted in `Stage4Params::editor_state` (`#[persist = "editor-state"]`, default 1170 x 315). The panel (1560 x 420 logical) scales with egui's zoom factor to fit and is centred; resizing uses the `nih_plug_egui` corner handle, which cannot enforce the aspect, so extra window area is letterboxed. HiDPI comes from the host scale factor. |
| Dimming | Controls whose `Binding::Bound` host id is missing or not written by the sink get a translucent overlay and the tooltip "not automatable in the plugin yet". `UiOnly` / `Unsupported` controls stay as drawn. A control sharing its rectangle with a live or passive one (a Shift function) is not dimmed. |
| Menus | Aux KB menu items map to `auxkb_*`; the synth choice order (`---`, `A--`, `-B-`, `--C`, `AB-`, `A-C`, `-BC`, `ABC`) is converted to the host layer bitmask explicitly (`map_settings.rs`). Other menu items (including the new MIDI / Extern / Output items) have host parameters but are not mapped yet. |

Known limits: `fxx_filter_res` has host range 0..1 while the engine accepts 0..10; the synth GROUP copies, oscillator shape/wavetable/sample/FM selectors, dedicated filter/osc envelopes and pattern steps have no host parameter; `layer_scene_ii` has no panel command mapped; KB zones and Aux KB layer LEDs are engine-only (`engine:` bindings) and dimmed.

Status: tested headlessly (frame shape count, sink mapping, coverage, persistence, queue to `process()`). **Not verified in a host**: no DAW was available; see `docs/plugin-editor.md` for the smoke test.
